# 模拟交易系统产品设计方案

## 1. 产品定位

模拟交易系统用于在不接入券商 API、不触发真实下单的前提下，验证当前选股流程是否具备实盘化价值。

系统定位是：

- 低频、日线级、个人自用。
- 收盘后人工启动流程。
- 自动跑选股、复评、交易计划和模拟成交。
- 所有交易计划、订单、成交、持仓、净值数据持久化到本地文件系统。
- 先服务策略验证和交易纪律，不处理实时行情和实盘下单。

它不是高频交易系统，也不是券商交易终端。

## 2. 全局流程互斥

模拟交易会复用现有选股、导图、复评、归档链路，因此必须和“运行中心”共享全局互斥。

同一时间只允许一个后台流程运行：

- 运行中心流程运行时，模拟交易入口禁用。
- 模拟交易流程运行时，运行中心开始按钮禁用。
- 页面显示当前流程来源、步骤、运行目录，并提供跳转查看日志。
- 如果检测到进程已退出但锁仍存在，标记为 stale，允许用户清理。

建议新增全局锁：

```text
data/runtime/global_run_lock.json
```

示例：

```json
{
  "lock_id": "2026-05-12_153000_paper_trading",
  "owner": "paper_trading",
  "owner_label": "模拟交易",
  "run_dir": "data/runs/2026-05-12_153000",
  "pid": 12345,
  "started_at": "2026-05-12T15:30:00",
  "current_step": "检查当日选股结果",
  "status": "running"
}
```

## 3. 每日核心流程

用户进入 Workbench 的“模拟交易”页面，点击“运行今日模拟流程”。该流程不代表真实交易，也不默认模拟盘中成交；它只做日线级的计划生成和持仓估值。

流程先做一次全局检查：

1. 检查全局流程锁
   - 如果已有运行中心或模拟交易流程正在运行，则禁止启动。
   - 如果锁已失效，提示用户清理后重试。

2. 判断运行场景
   - 交易日、信号刷新时间前：使用上一完整信号日，不拉取 K 线，不跑今日选股，不调用 Gemini。
   - 交易日、信号刷新时间后：默认今日盘中没有执行计划，持仓不变；尝试用今日收盘数据生成下一交易日计划。
   - 非交易日：使用最近完整信号日，不拉取 K 线，不跑选股，不调用 Gemini。

3. 保存账户快照
   - 收盘前或非交易日：按最近完整信号日的收盘价估值。
   - 收盘后：按今日收盘价估值。
   - 如果当天没有手动执行过计划，持仓数量不变，只更新估值和收益曲线。

4. 生成交易计划
   - 收盘前或非交易日：保证最近完整信号日对应的执行日计划存在，例如昨日信号生成今日计划。
   - 收盘后：今日信号生成下一交易日计划。
   - 已存在的计划不重复生成，不覆盖用户确认、取消或执行过的计划。

收盘前或非交易日流程：

```text
检查全局锁
-> 使用最近完整信号日
-> 生成当前可用交易计划
-> 保存账户快照
```

收盘后交易日流程：

```text
检查全局锁
-> 尝试刷新今日信号
-> 今日已有完整归档则跳过选股和复评
-> 今日无完整归档则跑 B1 完整流程 + brick 跳过抓取流程
-> 保存账户快照
-> 生成下一交易日计划
```

## 4. 交易日语义

系统明确区分三个日期：

- `signal_date`：选股和复评日期，即收盘后形成信号的日期。
- `plan_date`：交易计划生成日期，通常等于 `signal_date`。
- `execute_date`：计划执行日期，通常是下一个交易日。

交易日判断优先使用 A 股交易日历：

- 优先读取 `data/trading/trading_calendar.json` 缓存。
- 需要未来执行日且缓存不足时，优先用 Tushare `trade_cal` 刷新并缓存。
- 如果没有 Tushare token 或请求失败，则用本地 K 线日期推导历史交易日，并只在缓存范围外退回周末规则。

示例：

```text
2026-05-12 收盘后运行流程
signal_date = 2026-05-12
plan_date = 2026-05-12
execute_date = 2026-05-13
```

如果 `2026-05-13` 收盘后运行每日流程，系统默认今日盘中没有执行计划，持仓数量不变；它用 `2026-05-13` 收盘价计算持仓估值和收益，并生成 `execute_date = 2026-05-14` 的计划。

如果用户希望模拟 `plan_2026-05-13.json` 的成交，必须在交易计划页手动执行。每日流程不自动补做盘中成交。

## 5. 用户操作场景

完整场景矩阵见 [模拟交易用户场景矩阵](paper-trading-user-scenario-matrix.md)。本节只保留核心路径。

交易日收盘前运行：

- 使用上一完整信号日。
- 默认不拉取 K 线，不跑今日选股，不调用 Gemini。
- 如果当前可用计划不存在，则用上一完整信号日生成；草稿计划仍需用户手动确认。

交易日收盘后运行：

- 默认今日盘中没有执行计划，持仓数量不变。
- 用今日收盘数据计算持仓估值和收益。
- 今日完整归档不存在时，才执行 B1 完整流程和砖型图跳过抓取流程。
- 用今日信号生成下一交易日计划。

非交易日运行：

- 使用最近完整信号日。
- 不拉取 K 线，不跑选股，不调用 Gemini。
- 只保证对应交易计划存在，并按最近完整信号日估值。

重复运行：

- 今日计划已经存在时，不重复生成今日计划。
- 今日完整归档已经存在时，不重复跑选股和复评。
- 如果尝试刷新今日信号但实际初选日期回退到上一完整信号日，则停止后续导图、复评和归档，避免浪费 Gemini 请求。

## 6. 第一版交易规则

默认参数建议：

```yaml
initial_cash: 20000
max_positions: 5
max_new_buys_per_day: 2
target_position_weight: 0.2
min_hold_days: 3
max_hold_days: 20
stop_loss_pct: 0.08
take_profit_pct: 0.18
buy_slippage_pct: 0.001
sell_slippage_pct: 0.001
commission_rate: 0.0003
min_commission: 5
stamp_tax_rate: 0.0005
```

买入规则：

- 只买当日复评推荐股票。
- 默认推荐阈值沿用 `suggest_min_score >= 4.0`。
- 每天最多新增 2 只。
- 总持仓最多 5 只。
- 单票目标仓位 20%。
- 买入数量按 100 股整数倍向下取整。
- 现金不足买入 100 股则跳过。
- 已持仓股票第一版不加仓。

卖出规则：

- 达到止损线则卖出。
- 达到止盈线则卖出。
- 持仓超过 20 个交易日则卖出。
- 持仓满 3 个交易日后，如果不再出现在推荐列表，则卖出。

成交价格：

- 买入价：执行日开盘价乘以 `1 + buy_slippage_pct`。
- 卖出价：执行日开盘价乘以 `1 - sell_slippage_pct`。
- 估值价：执行日收盘价。

## 7. 交易计划状态和操作交互

交易计划不是静态报表，需要有明确状态和操作。

计划状态流：

```text
草稿 -> 已确认 -> 待执行 -> 已模拟成交
                 -> 已跳过
                 -> 已取消
```

第一版支持：

- 确认计划：整份计划从草稿变为已确认。
- 取消计划：整份计划取消，不再执行。
- 取消单条订单：单条订单状态变为已取消。
- 查看原因：查看推荐原因、交易理由和风控检查。
- 查看成交：计划执行后查看成交价、手续费、滑点、成交金额。

推荐默认配置：

```yaml
auto_confirm_generated_plan: false
auto_execute_confirmed_plan: false
trade_calendar_provider: tushare
trade_calendar_path: data/trading/trading_calendar.json
trade_calendar_lookahead_days: 120
trade_calendar_raw_sample_files: 120
```

含义：

- 生成计划后先进入草稿状态，由用户确认。
- 每日流程不自动成交；已确认计划需要在交易计划页手动执行。

如果用户希望更自动，可以把 `auto_confirm_generated_plan` 改为 true。

## 9. Workbench 页面设计

新增一级导航：

```text
模拟交易
```

页面内部使用 tabs：

- 运行
- 交易计划
- 持仓
- 收益分析
- 配置

### 8.1 运行

目标：每天收盘后只需要看这一页并点击一次。

模块：

- 账户指标卡：总资产、现金、持仓市值、累计收益。
- 今日流程卡：B1 完整流程、砖型图跳过抓取、执行计划、生成新计划。
- 主按钮：运行今日模拟流程。
- 次按钮：只执行已有计划、只生成下一计划。
- 运行日志：复用 Workbench 深色日志框。
- 全局运行状态：如果运行中心已有任务，明确禁用模拟交易按钮。
- 当日结果检查：显示“已存在完整选股结果，将跳过选股流程”或“未发现完整结果，将从 B1 开始执行”。

### 8.2 交易计划

目标：查看下一交易日准备做什么。

表格字段：

- 序号
- 执行日期
- 代码
- 策略
- 方向
- 数量
- 参考价
- 预计金额
- 目标仓位
- 复评分数
- 风控
- 状态
- 操作

状态包括：

- 草稿
- 已确认
- 待执行
- 已成交
- 已跳过
- 已取消

操作包括：

- 确认计划
- 取消计划
- 查看原因
- 查看风控
- 查看成交
- 已取消

### 8.3 持仓

目标：查看当前持仓和浮动收益。

表格字段：

- 代码
- 策略来源
- 买入日期
- 持仓天数
- 数量
- 成本价
- 最新收盘价
- 市值
- 浮动盈亏
- 浮盈比例
- 止损价
- 止盈价
- 今日动作

### 8.4 收益分析

目标：判断系统是否值得进一步实盘化。

指标：

- 初始资金
- 当前总资产
- 累计收益率
- 最大回撤
- 胜率
- 盈亏比
- 平均持仓天数
- 交易次数
- 手续费合计
- 印花税合计

图表：

- 净值曲线
- 回撤曲线
- 每日收益
- 现金 / 持仓市值占比
- B1 / 砖型图收益贡献

### 8.5 配置

目标：让模拟交易规则可调整，但默认配置足够可用。

配置项：

- 初始资金
- 最大持仓数
- 每日最多买入数
- 单票目标仓位
- 最小持仓天数
- 最大持仓天数
- 止损比例
- 止盈比例
- 滑点
- 佣金
- 印花税

## 10. MVP 验收标准

第一版完成后，应满足：

- 能初始化 20000 元模拟账户。
- 能一键执行 B1 完整流程和砖型图跳过抓取流程。
- 能基于当日推荐生成下一交易日计划。
- 能把计划持久化到 `data/trading/plans/`。
- 能用下一交易日日线开盘价模拟成交。
- 能更新账户、持仓、成交、净值曲线。
- Workbench 能展示运行状态、计划、持仓和收益分析。
- 不接入任何券商 API。
- 不执行任何真实下单。

## 11. 暂不做

第一版暂不做：

- 实时行情。
- 实盘自动下单。
- 券商 API。
- 盘中止损。
- 分钟级撮合。
- 多账户。
- 高频交易。
- GUI 自动点击券商客户端。
